# StylesUI 0.7: design spec

- **Date:** 2026-10-12
- **Status:** Approved in conversation (2026-10-12)
- **Changes:** the Discard buttons and the confirmation from the [comment cards spec](2026-10-11-comment-cards-design.md), sections 4 and 6, and where every popover opens
- **Changes nothing in:** the store, the HTTP API, the CLI or the protocol. The canonical text does not change, so neither `anchoringVersion` nor `protocolVersion` changes.

## 1. Problem

StylesUI 0.7.0 adds what the comment cards had to do without or build by hand:

1. **No danger button.** The confirmation's Discard, which deletes a draft for good, is the same grey `secondary` as its Cancel. The comment cards spec chose that only because StylesUI 0.6.0 had no `danger` variant, and planned to switch once it had one.
2. **Hand-written focus.** `DiscardDraftButton` wraps the popover's toggle events to focus Cancel on opening and to return focus to Discard on closing, and moves focus itself on Cancel because WebKit doesn't focus a clicked button. `usePopover` now does all of this, through `initialFocus` and its own focus return.
3. **A placement override.** `ThreadCard.module.css` overrides StylesUI's anchor positioning so the confirmation opens from Discard's start edge. `top-start` now does the same.
4. **Popovers that line up with nothing.** Every other popover is centred on its button. Each button sits near the window's edge, so the browser pushes the popover back inside, 8px from that edge. The doc switcher's popover starts 36px before its title, and Appearance's sits under About.
5. **Submit review leaves focus behind.** It is a dialog, but opening it leaves focus on Submit, so a keyboard user has to Tab in to choose a verdict.

0.7.0 also renames the `outline` variant to `outline-primary` and adds members to `OverlayPlacement`. The app uses no `outline` button and handles no placement exhaustively, so neither needs a change.

## 2. Assumptions

1. **StylesUI is at 0.7.0**, already in `package.json` and the lockfile on this branch.
2. **Chromium and WebKit are the browsers that matter**, as the end-to-end tests run in them.
3. **The palettes need no tuning.** Every palette sets `danger`, `danger-hover`, `on-danger` and `danger-text` in light and dark, and StylesUI's palette showcase checks their contrast.
4. **One spec, not a capability map.** Every change follows from the same upgrade and ships as one feature.

## 3. Objective and success criteria

**Objective:** red marks the buttons that delete something at once, and the app's popovers use StylesUI's own placements and focus handling instead of local workarounds.

**Success looks like:**

1. **Discard.** The confirmation's Discard is `danger`. The unsaved-text question's Discard and Discard changes are `outline-danger`. The Discard on a draft, read or being edited, stays `secondary`, and Save and Submit stay `primary`.
2. **Confirmation.** It opens where it does today, with its start edge on Discard's and inside the comments, through StylesUI's `top-start`. `ThreadCard.module.css` has no placement override.
3. **Confirmation focus.** Unchanged in both browsers: Cancel has focus when it opens; Cancel and Escape return focus to Discard; a click outside leaves focus where the click put it; after a discard, focus moves as the comment cards spec says. `DiscardDraftButton` holds no focus code beyond passing `initialFocus`.
4. **Popovers.** Each opens from its button's edge, within 1px: the doc switcher's from its start edge, below it; Appearance's, About's and **+ Comment**'s from their end edges, below them; Submit review's from Submit's end edge, above it.
5. **Submit focus.** Opening Submit review focuses the radio of the verdict it opens with: Request changes when the user has drafts, and Approve when they have none.
6. **Nothing else moves.** The conformance test passes unchanged, `anchoringVersion` and `protocolVersion` are unchanged, and `pnpm verify`, `pnpm build`, `pnpm test:e2e` and `fallow audit` pass.

## 4. Decisions

| Topic | Choice | Alternatives considered | Why |
| --- | --- | --- | --- |
| Which Discards are red | Those that delete something with no step after: the confirmation's, and the unsaved-text question's | Every Discard `outline-danger`; every Discard `danger`; none | Chosen by the user, after comparing screenshots of the three. The Discard on a draft only opens the confirmation, so it stays grey, and a list of drafts stays as calm as the comment cards spec chose to keep it |
| The confirmation's Discard | `danger` | `outline-danger` | It is the confirmation's answer, beside a grey Cancel, as the comment cards spec planned |
| The unsaved-text question's Discard | `outline-danger` | `danger`; `secondary`, as now | It throws the unsaved text away at once. Filled, it would give the question two filled answers. Save, which takes focus, stays the only one |
| The confirmation's focus | `usePopover`'s `initialFocus` and focus return | Keep the hand-written code | StylesUI 0.7.0 does the same in both browsers, including where WebKit leaves focus on the page after a click on a button. The comment cards' unit and end-to-end tests pass against it unchanged |
| The confirmation's placement | `top-start` | Keep the CSS override | It gives the same box. StylesUI also narrows it, then flips it, when it is short of room, and the override reached into StylesUI's anchor positioning |
| Other popovers | Aligned with the edge of their button nearer the window's edge | Centred, as now | The browser's push back inside the window lines a popover up with nothing. Aligned, each opens from its button, and the menus read as dropping from it |
| Submit review's initial focus | The radio of the verdict it opens with | The dialog's own Submit; leave focus on the trigger | It is a dialog, so focus moves into it, as the confirmation's does. The verdict is its first choice, and the arrow keys change it. Focusing the dialog's Submit would let Enter send at once |
| Which radio | The checked one. The popover holds a verdict only while it is open, and clears it on closing, so while it is shut the verdict is worked out from the draft count | Reset the verdict when it opens, and find the radio from the draft count; work the verdict out from the draft count at every render | `usePopover` focuses `initialFocus` before it reports the opening, so a reset on opening comes too late for the focus, and the radio and the verdict would be found two ways that must agree. Worked out at every render, the verdict would turn from Request changes to Approve if the drafts went while the popover was open |

## 5. Behaviour

### Buttons

| Where | Buttons, start then end | Variants |
| --- | --- | --- |
| A draft, read | Discard; Edit | `secondary`, `secondary` |
| A draft's editor | Discard; Cancel, Save | `secondary`, `secondary`, `primary` |
| The Discard confirmation | Cancel, Discard | `secondary`, `danger` |
| An editor asking about unsaved text | Discard or Discard changes; Keep editing, Save | `outline-danger`, `secondary`, `primary` |

Hovering the confirmation's Discard darkens it to `--sui-color-danger-hover` in a light palette and lightens it in a dark one. Hovering an outline tints it with its own red at 8%. While the delete runs, the confirmation's Discard is busy, as now.

### Popovers

| Popover | Its button | Placement |
| --- | --- | --- |
| Doc switcher | The title, at the start of the top bar | `bottom-start` |
| Appearance | At the end of the top bar | `bottom-end` |
| About | At the end of the top bar | `bottom-end` |
| **+ Comment** menu | At the end of the comments' header | `bottom-end` |
| Submit review | At the end of the review bar | `top-end` |
| Discard confirmation | At the start of a card's row of buttons | `top-start` |

Each keeps StylesUI's fallbacks: short of room, an aligned popover narrows, and flips to the other side or edge only when even its narrowest width does not fit. The icon buttons' tooltips keep their centred `bottom` placement.

### Focus

- **Discard confirmation:** as section 3 says. `usePopover` returns focus to whatever had it before the popover opened, which is Discard, or to Discard when the browser leaves focus on the page.
- **Submit review:** opening it focuses the radio of the verdict it opens with. Escape, Cancel and submitting close it as now, and `usePopover` returns focus to Submit.

## 7. Conventions

The `coding-standards` plugin's TypeScript, React, comments and Vitest standards apply, and win over any code in this spec. Follow the code around each change: a comment says why, not what, in a sentence with no full stop at the end; tests are named `must … when …`; every new export is used by code or tests in the same commit, or `fallow audit` fails the commit.

## 8. Testing

### Unit and component tests (`web` project, jsdom)

- **`ThreadCard.test.tsx` and `ThreadSidebar.test.tsx`:** the existing Discard and focus tests pass unchanged. The coding standards keep styling out of unit tests, so the variants are checked by hand.
- **`ReviewBar.test.tsx`:** "must focus $verdict when the user opens the popover with $submit", for one draft and for none; "must focus Request changes when the user opens the popover again after choosing Approve"; and "must focus Request changes when the user opens the popover again after writing a draft". The existing "must not submit a request for changes when the drafts go while the user has it chosen" passes unchanged.

### End-to-end tests (Playwright, Chromium and WebKit)

jsdom lays nothing out, so where the popovers open is checked here.

- **`layout.e2e.ts`:** "must open the $popover popover $side its button, from the button's $edge edge", for each popover in section 5 but the confirmation. Each finds its popover through the button's `aria-controls`, and checks the popover clears the button.
- **`comments.e2e.ts`:** "must keep the draft and return focus to Discard when the user $action in the confirmation", for Escape and for a click on Cancel, which WebKit doesn't focus. The other confirmation tests, including "must open the confirmation inside the comments, from Discard's start edge", pass unchanged.
- **`review.e2e.ts`:** "must focus the verdict Submit review opens with, then return focus to Submit when the user clicks Cancel".

### By hand

In light and dark mode and in every palette, look at the confirmation, the unsaved-text question and each popover. Check each button's variant against the table in section 5.

## 9. Commands

```sh
pnpm vitest run --project web src/web/components                         # the component tests above
pnpm test:e2e src/e2e/layout.e2e.ts src/e2e/comments.e2e.ts src/e2e/review.e2e.ts   # Chromium and WebKit
pnpm verify                                                              # lint, format check, typecheck and tests
pnpm build                                                               # dist/cli.js and dist/web
pnpm test:e2e                                                            # every end-to-end test
pnpm exec fallow audit                                                   # what the pre-commit hook runs
```

## 10. Boundaries

- **Always:** keep the code that runs inside `src/web`, so the server, the CLI and `src/shared` don't change; beyond it, change only the StylesUI version and lockfile, this spec and the end-to-end tests; run the component tests and the end-to-end tests in both browsers before committing; check light and dark mode.
- **Ask first:** changing StylesUI; making a Discard that opens the confirmation red; adding a dependency.
- **Never:** change `anchoringVersion` or `protocolVersion` for this; let a Discard that deletes a saved draft skip its confirmation; edit older specs, which record the design as it was.

## 11. Out of scope

- **Appearance taking focus as it opens.** It is also a dialog, and `initialFocus` on Mode would match Submit review, but the user chose Submit review alone for now.
- **Aligned tooltips.** The top bar's icon buttons keep their tooltips centred.
- **A `success` Submit for Approve.** The button would change colour as the radio changes, and Save and Submit stay the only filled buttons.
