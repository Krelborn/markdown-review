For Claude Code, Codex, OpenCode and any agent with a shell

Your agent writes the plan. You review it.

Markdown Review opens the plans, specs and design notes your coding agent writes in your browser, the way you would review a pull request. Comment, submit, and the agent edits the docs and answers every comment.

Comment on anything

Point at exactly what needs to change

Comments hold on to the words you chose, and follow them when the agent edits the doc.

  • A passageSelect text, even across paragraphs, and click Comment.
  • A block, or severalClick the + in the margin, or drag down it, for code, diagrams and HTML.
  • A table, list or sectionClick the bracket at the margin's far left, or ⌥-click the margin.
  • The whole doc, or the whole reviewFrom + Comment at the top of the comments.

Threads

Every comment gets an answer

The agent resolves each thread, saying what it changed, or replies with a question. The page shows it at once, and re-renders the doc in place. 

$ markdown-review resolve 1 "Added a Failure modes section: the limiter fails open."
$ markdown-review reply 2 "Should a single API key be able to override its plan's limits too?"
$ markdown-review poll
  • Drafts, Open, Outdated and ResolvedGrouped the way you would expect from a pull request.
  • Reply to reopenResolved threads stay folded until the agent answers in them.

Submit

Hand it back with a verdict

Comments are drafts until you submit them, and every submit says what the agent does next.

  • ReviseThe agent revises the docs, answers each comment, and waits for you again.
  • Go aheadThe review ends. The agent addresses any drafts, then carries on with its next task.
  • Hand back to agentThe review ends, and the agent stops and waits for you in the chat.

Many docs

Review a set of docs together

A plan rarely comes alone. The agent can add every doc it wrote to the same review, and you submit them in one go.

  • This doc and All docsSwitch between one doc's comments and every doc's.
  • Links stay in the appA link to another markdown doc in the repository opens it for review.

Rendering

Reads like GitHub

Tables, task lists, alerts, syntax-highlighted code and Mermaid diagrams, with the frontmatter in a Properties panel. Light or dark, in four palettes.

Get started

Set up in a minute

Markdown Review runs on your machine: a CLI that starts a small server for each repository and serves the app on 127.0.0.1. No MCP server, plugin or account.

Needs Node.js 22.22.2 or later, 24.15 or later, or 26 and later, on macOS or Linux. More in the docs.

  1. 1. Install the CLI
    npm install --global @krelborn/markdown-review
  2. 2. Teach your agent the review loop
    markdown-review install-skill --global

    Writes the skill to ~/.claude/skills for Claude Code and ~/.agents/skills for Codex, Gemini CLI and most other agents. Start a new agent session afterwards.

  3. 3. Ask for a review

    I'd like to review the plan in markdown-review

    The agent opens the doc, waits for your comments, edits the doc and answers each one, until you say go ahead.
